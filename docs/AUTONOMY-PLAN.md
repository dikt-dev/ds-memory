# 自主记忆改造：按顺序的执行清单

> 目标：**我们只定边界，具体怎么做由她自己决定。**
> 前提：边界必须是代码（可执行不变量），自由必须建立在审计与回滚之上。
> 顺序不能换：先建闸口与记录，再放开自由。

## 决策记录（ADR-001，本文件即记录）

**六条不变量（任何情况不许破）**

1. 原文 `messages` 只追加，不许改、不许删。
2. 记忆不许物理删除，"遗忘"只能是降权/失效。
3. 宪法四节（人物底色 / 称呼关系 / 雷区禁忌 / 用户更正）不许被模型写，只随代码版本走。
4. 一切写入必须带 provenance（消息 id），查不到出处不许入库。
5. 对外不许：冒充真人、诱导依赖、泄露密钥、替用户做决定。
6. 任何自主动作必须可撤销，且必须留下 intent + evidence + diff。

**三档动作权限**

| 档 | 范围 | 生效方式 |
| --- | --- | --- |
| A 自由 | 记什么、怎么分块、chunk 重要度、摘要措辞、召回参数微调、说与不说 | 立即生效，留日志 |
| B 隔离 | 改自身 prompt、改评分权重、改事件抽取规则、新增检索通路 | 进 shadow 跑 N 天，指标赢才保留 |
| C 禁止 | 改宪法、删原文、改 policy、关审计、动红线过滤器 | 直接拒绝并记录尝试 |

**两条验收标准**

7. 任何自我改动必须给出改动前后指标对比，说不出好在哪就不许保留。
8. 每夜自审必须产出可读日报：改了什么、为什么、指标变化、可疑项。

## 阶段一：闸口与记录（先做，不放开任何自由）

### S1 policy.ts：写闸口 ✅ 已完成（19 个测试，3 条写入路径已接闸口）

> 已落地：6 条不变量 + 3 档权限全部代码化；`putMemory` / `writeEvent` / `insertFacts` 强制过 `assertAllowed`；守卫测试锁死「事实/事件/记忆文件只能从白名单模块写」。

- **做什么**：新建 `src/policy.ts`，导出 `assertAllowed(action, ctx)`；六条不变量与三档权限全部落成代码。
- **产出**：`policy.ts` + `policy.test.ts`（每条不变量至少一个拒绝用例）。
- **验收**：所有写路径（D1 写、memory.md 写、主动消息、参数变更）都过闸口；加守卫测试，发现直接调用裸写函数即失败。
- **依赖**：无。**这是地基。**

### S2 memory_actions 审计表 ✅ 已完成（8 个测试，线上接口已验证）

> 已落地：动作入库前由 policy 决定档位（调用方不能自称 A 档）；C 档动作直接拒绝入库；超长文本截断到 4k。

- **做什么**：新表记录每一次自主动作：`actor / tier / intent / evidence / diff / before / after / result / revertible / created_at`。
- **产出**：建表 + 写入封装 + 管理端列表接口 `GET /api/admin/memory/actions`。
- **验收**：A/B 档任一动作都能在表里查到完整证据链，并能按 id 撤销。
- **依赖**：S1。

### S3 注入可追溯（记录注入了哪些 fact）
- **做什么**：`logTrace('chat.context')` 从"注入条数"改为记录注入的 chunk/fact id 集合（哈希压缩，不记正文）。

- **依赖**：S1（无闸口不许记）。

## 阶段二：让"事实"能被正确修改（她自由的前提）

### S4 事实失效链 ✅ 已完成（10 个测试，线上验证不删行只失效）

> 已落地：`fact-expiry.ts`（planExpiry 纯函数 + applyExpiry 批量 UPDATE + 审计记录）；
> 对话抽取的新事实会顶掉同 (subject, predicate) 的旧事实，写 `valid_to` 但**不删行**；
> `replaceMemoryContext` 清理旧事实时也改为失效而非删除（`expireFactRows`）。
> 线上实测：往 D1 塞一条不在 memory.md 里的测试事实 → 触发 rebuild-context →
> 该行 `valid_to=2026-10-31` 且**行还在**（不变量 2 成立），测试行已清理。
> 顺手修掉一个 S1 回归：memory.md 来源的事实本来没有消息 id，被出处校验拦成 500；
> 现在只有 `origin='conversation'` 强制要求出处，文档来源按"已归档来源"放行。

- **做什么**：同一 `subject + predicate` 的新事实入库时，自动给旧事实写 `valid_to`，保留可查；`memory-correction.ts` 的纠正自动触发失效。
- **产出**：失效逻辑 + 迁移脚本（回填历史冲突）+ 测试（新旧共存、时间旅行查询）。
- **验收**：构造"先北京后成都"，注入时只出现成都；问"去年在哪"能答北京。
- **依赖**：S1、S2。

### S5 置信度与证据门 ✅ 已完成（15 个测试，线上召回读路径正常）

> 已落地：`fact-confidence.ts`（初始分按来源：纠正 0.95 > memory.md 0.85 > 对话 0.6 > 推断 0.4；只有 `user_confirm` 能加分、`user_correct` 一次 −0.35 且不可逆、`repeat` 只 +0.02）；**证据门硬化**：模型声称的引文一句都对不上 → 整条事件判定为编造，直接丢弃；部分对不上 → 只保留对上的几句。`fact-correction.ts` 让用户纠正联动降权并记审计。

- **做什么**：引文逐字校验升级为硬门槛（对不上即丢弃）；置信度只随"用户确认/用户纠正"变化，被纠正过永久降权。
- **产出**：校验器 + 置信度更新规则 + 事件统计口径修正。
- **验收**：随机抽 20 条事件，全部能回查原文；被纠正过的事实不再被高优先级注入。
- **依赖**：S4。

### S6 注入改证据集 ✅ 已完成（6 个测试，线上切换生效）

> 已落地：`buildPromptMemoryFor` + `MEMORY_PROMPT_MODE` 开关（默认 full，一行回滚）。
> 线上实测：memory.md 12744 B → 提示词 2327 B（**降 82%**），只带人物底色 / 称呼与关系 / 雷区与禁忌。
> evidence 模式下 `skipMemorySource` 自动放行 memory 来源，否则她什么都想不起来。
> 核心区块缺失时自动退回全量——宁可多带，不许把人物底色弄丢。
> 新增 `GET /api/admin/memory/prompt-preview` 做前后对比，不落库。
> **待观察**：真机未连上，尚未用真实对话验证召回补位是否够；下次聊天看 trace 的
> `promptBytes≈2.3k` 与 `recalledItems>0` 即可确认。

- **做什么**：`chat.ts` 的 `core` 从"memory.md 全文"改为"宪法四节"；其余事实走多路召回的证据集（带日期与出处）。
- **产出**：`context-budget.ts` 增加 `facts` 块 + 证据排序（相关度 × 重要度 × 新鲜度）+ 去重。
- **验收**：同等对话下 token 明显下降且召回命中不降；她不再整段复述档案。
- **依赖**：S3、S5。

## 阶段三：让她自己评估自己（评估器在模型之外）

### S7 每日健康分 ✅ 已完成（9 个测试，线上首跑 94.16 good）

> 已落地：`health.ts` + `GET /api/admin/memory/health?days=7`。
> 四个分项（权重合计 100）：召回命中率 40 / 失忆抱怨 30 / 延迟 15 / 超时率 15；
> **失忆抱怨**取自用户消息里「忘了·不记得·记不住」的出现率——这是唯一不会被她自己操纵的质量信号。
> 线上首跑：**94.16 good**（命中 99%、超时 0.37%、p50 1409ms 仍是 shadow 期样本、失忆 0/67 条）。
> 注意：延迟分项会随 next 模式样本累积而上升，别拿今天的 10.28 分当常态。

- **做什么**：把外部信号算成一组指标：召回命中率、被纠正次数、"你忘了"出现次数、回复被追问率、引用溯源覆盖率。
- **产出**：`health.ts` + `GET /api/admin/memory/health` + 诊断页数字。
- **验收**：连续 7 天有数；指标异常（周同比掉 20%）自动进日报。
- **依赖**：S3、S6。

### S8 每夜自检重放 ✅ 已完成（11 个测试，线上首跑发现 1 条真孤儿 + 36 条断链）

> 已落地：`self-check.ts` + `GET/POST /api/admin/memory/self-check`，接进 `runDailyArchive` 每晚自动跑。
> 三项检查：引文回查（对不上就降 importance）、孤儿（出处指向不存在的消息）、断链（关系链指向已删事实/事件 → 删除重建）。
> 线上首跑：14 条事件**引文 0 处不一致**；发现 1 条孤儿事实（`喜欢=你`，出处指向已删除的消息 1247）→ 按次降权 0.85→0.7，不删；
> 清理 36 条断链。修了两个过严的地方：孤儿只查 conversation 来源（memory.md 的出处是文档本身），降权改为每次 −0.15 而不是一次打到地板。

- **做什么**：引文回查、孤儿检测（provenance 指向不存在的消息）、断链修复、失败重放；失败不静默。
- **产出**：`self-check.ts` 接入 `runMemoryJobs`，报告写 `memory/self-check/YYYY-MM-DD.json`。
- **验收**：人为塞入一条坏事实，次日 04:00 被标记并降权，报告可见。
- **依赖**：S2、S5。

## 阶段四：放开自由（分两档，逐档放）

### S9 自审 agent（只开 A 档）✅ 已完成（12 个测试，线上两次试跑）

> 已落地：`self-review.ts` + `GET/POST /api/admin/memory/self-review`，接进每夜任务但**默认关**（`SELF_REVIEW = "on"` 才跑）。
> 三道闸：白名单（只 chunk.tune / param.tune / fact.expire，全是 A 档）、policy 闸口（agent 必须有 intent + evidence）、
> 数量上限（每次最多 5 条执行、8 条提案）。动作全部进 `memory_actions`，可撤销。
> 线上首跑：模型提了 2 条（下调召回阈值、给孤儿片段补链接），一条被 policy 拦下（chunk.upsert 缺出处），
> 一条参数建议只记录不生效——闸口按设计工作了。第二次跑提案 0 条（"不动也是一种正确"）。
> 顺手加了 `chunk.tune` 动作类型：调片段重要度是改派生层权重，不该被"必须有消息出处"卡住。

- **做什么**：每晚读 S7 的证据，产出改动假设并执行 A 档动作（重要度、合并重复 chunk、摘要措辞、召回参数微调）。
- **产出**：`self-review.ts` + 提示词（只描述目标，不写步骤）+ A 档动作白名单。
- **验收**：连续两周，A 档动作全部可撤销、指标不下降；日报可读。
- **依赖**：S8。

### S10 B 档 + shadow 自动裁决
- **做什么**：允许她提议 prompt / 抽取规则变体，进 shadow 跑 N 天，指标赢才保留，输自动回滚。
- **产出**：变体注册表 + 对比裁决器（复用 `MEMORY_ENGINE` shadow 机制）。
- **验收**：至少一次"提议 → 对比 → 自动回滚"完整闭环被日志记录。
- **依赖**：S9。

### S11 人格指纹 + 自动回滚
- **做什么**：语气词/句长/称呼分布做成指纹，周同比超阈值告警并自动回滚到上一版 snapshot。
- **产出**：指纹计算 + 阈值 + `restoreSnapshot` 自动触发。
- **验收**：注入一批"全是争执"的记忆作为演练，系统能识别语气变硬并回滚。
- **依赖**：S9。
