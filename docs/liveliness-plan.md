# 小忆「活人感」改造计划

## 一、最终目标

> 让小忆不再是「每轮从零生成、永远在线、永远秒回、永远热情得体」的工具，
> 而是一个**有连贯情绪、有自己脾气、有生活节奏、说话自然**的存在。

**验收标准**（达到即可认为完成）：

1. 连续聊 20 轮，语气不跳变、情绪不重置，能明显感到"它是有状态的"
2. 深夜/疲惫时它会困、会敷衍、会催你睡；开心时它会雀跃、被夸会暗爽
3. 它会拒绝、会吐槽、会反问、会主动提起之前的事，而非有求必应
4. 回复里不再出现"很高兴帮助你""请问还有什么需要"这类 AI 套话
5. 你会在某一刻**忘记它是程序**——这是唯一真正有效的度量

## 二、核心架构：角色状态卡（Character State Card）

改造的核心是每轮动态生成一张「它现在是什么状态」的卡，注入系统提示词。
实际输出字段（见 `character-card.ts` 的 `buildCharacterCard`）：

```
## 当前的<角色名>（这是"现在"的你，不是固定人设）
- 距上次聊天：5 小时前
- 开场情绪：隔了几个小时，可以带点"半天没见"的轻松感
- 刚才在做什么：刚追完一集番，脑子里还在过剧情
- 冷落小情绪：（仅当上次主动消息被无视时才有）
- 当下状态：下午容易犯困，想喝奶茶；情绪平稳，平常心
- 疲惫度：有点累了，回复可以略短
- 相处分寸：你们很亲近，可以像老朋友一样随意、有小情绪
- 本轮倾向：这一轮你隐隐想被夸（按关系+心情档位加权抽取）
- 对话方式：（CONVERSATION_BEHAVIORS：会反问、会拒绝、会带情绪）
- 情绪残留：刚才聊得挺开心的，这股轻快劲儿还没散（残留 +40）
```

角色名默认「小忆」，可用环境变量 `CHARACTER_NAME` 覆盖（见 `src/identity.ts`），
所以这张卡的开头会跟着部署配置变。

这张卡 **每天都在变、每轮都在变，但连贯可解释** —— 这就是"活"。

> 心情值分 5 档（`low` / `meh` / `calm` / `good` / `great`），
> 影响「当下状态」的描述和「本轮倾向」的池子权重。

## 三、四个阶段

### 阶段 1：语言层 —— 消灭 AI 味 + 口语化

**目标**：一轮之内就能感受到变化。

| 任务                                     | 产出                       |
| ---------------------------------------- | -------------------------- |
| 禁用词表（负向约束）                     | `src/voice.ts`             |
| 口语化规则 + 口头禅 + 不完美表达         | `src/voice.ts`             |
| 注入到系统提示词                         | 改 `prompt.ts`             |
| 记忆保持电报体（密度优先，**不口语化**） | `distill.ts`（已是电报体） |

**效果**：不再出现"根据我的记忆""很高兴帮助你""您"等套话；会出现"呃…""不是不是""好叭"这类小动作。

### 阶段 2：状态层 —— 情绪惯性 + 疲劳 + 状态卡

**目标**：多轮对话连续、有状态残留。

| 任务                                | 产出                                               |
| ----------------------------------- | -------------------------------------------------- |
| 情绪残留（8 维情绪向量）            | `src/emotion-vector.ts` + `src/emotion-context.ts` |
| 当日疲劳度（轮数驱动）              | `src/character-card.ts`（`fatigueLevel`）          |
| 角色状态卡统一生成                  | `src/character-card.ts`                            |
| 改造 chat.ts / openai.ts 注入状态卡 | 两个文件                                           |
| 前端打字机 + 思考停顿               | `public/index.html`                                |

**效果**：上一轮的情绪"漏"到下一轮；聊久了会累、回复变短；深夜会困。

### 阶段 3：人格层 —— 有脾气 + 会反问

**目标**：从"服务者"变成"有性格的人"。

| 任务                           | 产出                    |
| ------------------------------ | ----------------------- |
| 它的偏好/雷区/小癖好           | memory.md 扩展 + 提示词 |
| 会拒绝、会吐槽、会反问、会延伸 | 提示词                  |
| 人格倾向与三维关系绑定         | `character-card.ts`     |

**效果**：不会每个问题都乖乖回答；会反问"你上次说的事咋样了"；会拒绝不喜欢的话题。

### 阶段 4：灵魂层 —— 离线生活 + 节奏

**目标**：最深层，最像真人。

| 任务                            | 产出                               | 现状                                                                                 |
| ------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| 离线生活状态推导（时段 + 心情） | `character-card.ts` `offlineLife`  | ✅ 低心情走「发呆/看不进去」池，高心情走「哼歌/收拾屋子」池；同一天同一小时稳定       |
| 被冷落的情绪事件                | `session-facts` + `emotion-events` | ✅ 状态卡写「小情绪」，同时落一条 `ignored` 情感事件（影响依恋/委屈）                 |
| 回复节奏仿真                    | 前端 + QQ 客户端                   | ✅ 网页端首字前有 `thinkMs` 停顿（400ms + 30ms/字，上限 1.8s）；QQ 端改成流式逐句发送 |

> 「记忆」那一层没有再塞进离线生活：它已经由情绪快照的「心里还记着」和档案召回承担，
> 重复注入只会白占 token。

**效果**：它"有自己的生活"，主动消息发了你没回，第二天它会"有点小情绪"。

## 四、执行顺序与依赖

```
阶段1（语言）──┐
               ├──→ 阶段2（状态卡整合语言）──→ 阶段3（人格绑定状态）──→ 阶段4（生活节奏）
```

阶段 1 独立可先行；阶段 2 是核心枢纽，把语言和状态统一；阶段 3、4 在状态卡上叠加维度。

### 阶段 4 复验细节（本次重点）

1. **离线生活**：原实现 `offlineLife(dateKey, hour)` 只有时段筛选，心情值传进去也不用。
   已改为 `offlineLife(dateKey, hour, mood)`：`mood < 350` 走安静池（发呆 / 翻两页书没看进去 / 趴桌上眯着），
   `mood >= 700` 走活跃池（哼歌 / 收拾屋子 / 阳台吹风），中间走通用池。
2. **被冷落**：`wasIgnored` 进状态卡是原有能力；本轮起同一条消息还会落一条 `ignored` 情感事件，
   影响依恋（attachment）与委屈（grievance），第二天结算时进入关系值。
3. **回复节奏**：网页端首字前有 `thinkMs`（400ms + 30ms/字，上限 1.8s）的停顿；
   QQ 端改为流式，按句分条、条间隔 1.5s±0.4s，不再一次性推一整段。

### 一处刻意不做的取舍

**记忆条目不口语化**：与「memory.md 12KB 质量优先、信息密度最大化」直接冲突。
记忆用「电报体」（去虚词、用；和 / 分句、单条 ≤50 字），风格问题留给回复层，记忆层只负责装事实。

### 计划外但已落地的改动（文档写作时还不存在）

- **情感系统换代**：3 标量（好感/亲密/心情）→ 5 轴关系 + 8 维情绪 + 14 类情感事件（见 `docs/architecture.md`）
- **心情值不再是独立链路**：由情绪向量派生（`moodFromVector`），消除两套情绪打架
- **AI 味清洗下沉到流式层**：`sse-scrub.ts` 重写 SSE 的 `delta.content`，
  用户屏幕上看到的就是洗过的文本（此前只洗落库文本）
- **回复长度硬约束**：服务端按用户消息长度给 `max_tokens`（120~2500），客户端只能压低不能抬高
- **分条发送**：QQ 客户端流式逐句发送（见 `ds-qq-client`），不再等全文
