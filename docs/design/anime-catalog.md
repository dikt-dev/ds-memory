## 为什么按季拆

之前的表把「进击的巨人 87 集」写成一个数，这会带来两个具体的错：

| 错法 | 后果 |
| --- | --- |
| 一季一季追，但只记 87 | 看到第 25 集时不知道第二季在哪，台词会编 |
| 追平第一季就当「完结」 | 她说「看完了」，其实还有 5 季，人设立刻塌 |

所以 `ai_arc.key` 用 `作品名#季`（如 `进击的巨人#S2`），
`cursor` 是这一季的集数，`cursor_max` 是这一季的总集数。

## 挑片原则

- 口味稳定才像人：偏治愈 + 日常，偶尔热血，虐的只在大情绪后看
- **按心情挑 vibe**：`healing` 心情低、`hype` 精神好、`mystery` 无聊想刺激、`sad` 想哭一场
- 长番放进来是为了「追了半年」这种真实感——现在是真的能追半年

## 数据格式

```ts
/** 一条「季」= 一条可独立推进的弧线（ai_arc 的一行） */
interface SeasonEntry {
  title: string;      // '进击的巨人'
  season: string;     // 'S2' / '最终季' / '续章 上'
  year: number;       // 2017
  episodes: number;   // 12
  vibe: 'healing' | 'daily' | 'hype' | 'mystery' | 'sad';
  status?: 'airing' | 'finished';  // 连载中 → 追平后进 waiting
  reason?: string;    // 她为什么喜欢（只在第一季上写）
}

/** 作品级：只用来排序和展示，不参与进度计算 */
interface AnimeSeries {
  title: string;
  seasons: SeasonEntry[];   // 按年份升序
}
```

## 三条规则

1. **一季一条进度**：`key = 作品名#季`，`cursor_max = episodes`
2. **追平一季的处理**：
   - 还有下一季 → 该季 `finished`，下一季可以是新 `active` 弧线（她可以说「接着看第二季」）
   - 没有下一季且片单标 `airing` → `waiting`，`next_update_at` = +7 天
   - 没有下一季且已完结 → `finished`，之后只能重温
3. **连续多季不能跳**：`S1` 没看完不能开 `S3`（可以开 `S2`？不行——同一部作品同时只允许一条 active 弧线）

## 两个注意

1. **集数以本表为准**，不要模型自己数；表里没有的作品不追
2. **她可以不喜欢某部**：片单是候选池，不是必看清单；抽到不感兴趣的就换一部，连续两次不感兴趣就降低权重
