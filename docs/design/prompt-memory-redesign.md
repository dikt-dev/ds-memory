# 任务书：提示词与记忆分离（重设计）

> 状态：设计稿，待拍板
> 范围：ds-memory 的提示词组装 + 记忆文档结构；ds-mobile 不改
> 前置：数据已全量清空（2026-11-04），从白纸开始

---

## 1. 目标

把「她是谁」和「发生过什么」彻底拆成两份文档、两条生命周期、两套写入方。

三条硬规则：

1. **事实只进记忆，人格只进人设**，同一条信息不得两边都有
2. **雷区归人设**，不归记忆（她是“不能接受什么”，不是“经历过什么”）
3. **记忆每条带出处**（日期 + 消息 id），人设不需要出处

---

## 2. 现状问题

### 2.1 串味（设计缺陷）

| # | 问题 | 后果 |
|---|---|---|
| 1 | `## 人物底色` 住在 memory.md | 人设内容由系统提炼改写，人格会悄悄漂移 |
| 2 | `## 记忆怎么用` 写死在 prompt.ts | 改记忆策略要动人设代码 |
| 3 | 提示词引用记忆分区名（“下面「人物底色」就是你本人”） | 人设知道了记忆的目录结构 |
| 4 | `## 雷区与禁忌` 在记忆里 | 雷区被当成“经历”，会被合并、裁剪 |

### 2.2 踩过的三个坑

| 坑 | 现场 | 根因 |
|---|---|---|
| 否认写过日记 | “日记？本小姐什么时候写过日记” | 只有内容按需，没有存在声明 |
| 两地天气对调 | “杭州下起来了，你深圳晴着吧” | 城市写进提示词，主语归属规则缺失 |
| 编细节被拆穿 | 说出并不存在的日期和原话 | 没有“不确定就说不记得”的约束 |

### 2.3 工程问题

| # | 问题 |
|---|---|
| 1 | 按需内容若进稳定前缀，整段缓存失效（命中价 0.04 → 未命中 2.0） |
| 2 | 关键词触发天然漏检（“你那个呆毛”命中不了“外貌”） |
| 3 | persona.md 目前是自由 Markdown，无法校验长度、无法 diff、无法做编辑表单 |

## 3. 设计

### 3.1 文档模型

| 文档 | 只回答 | 谁写 | 变化频率 | 存放 |
|---|---|---|---|---|
| `persona.md` | 她是谁、怎么说 | 人 | 人工修改 | R2 |
| `memory.md` | 发生过什么 | 系统提炼 + 用户更正 | 每天 | R2 |

互相不引用：persona 不出现人名/城市/日期，memory 不出现性格/语气/雷区。

### 3.2 persona.md 结构：四个必填槽 + 三张可选卡

```markdown
---
version: 1
name: 鲸鱼娘
self_call: 本小姐
role: 损友
---

## 说话     必填 ≤300 字
## 性格     必填 ≤300 字
## 边界     必填 ≤200 字
## 能力     必填 ≤80 字
```

可选卡（不写就不存在）：

| 卡 id | about（给 embedding 用） |
|---|---|
| `appearance` | 她的长相、穿着、身体特征，被问到长相或看照片时用 |
| `people` | 她身边的人，被问到某个具体的人时用 |
| `past` | 以前发生过的事，被问“还记得吗”时用 |
| `diary` | 她的日记内容，被问到日记、要日记看时用 |

### 3.3 memory.md 结构：按稳定性分区

```markdown
## 稳定事实   住哪、做什么、家人（同一人只留最新一条）
## 偏好       喜欢/讨厌/习惯
## 承诺与待办  带状态 [进行中] [搁置] [已完成]
## 经历       - [YYYY-MM-DD] 发生了什么（msg:1234）
## 更正       - [YYYY-MM-DD] 他明确改口的说法（优先级最高，永不自动清理）
```

取消 `## 近期动态`（7 天后并入经历），取消 `## 人物底色`（归人设），取消 `## 雷区与禁忌`（归人设边界）。

### 3.4 触发：embedding，不是关键词

```
卡片的 about → 预计算 embedding，存 KV（改文档时失效重算）
用户这一轮消息 → 一次 embedding（bge-m3，已有）
相似度 ≥ 0.45 → 带这张卡
```

日志记录：本轮带了哪些卡、分值、最接近但没达标的卡（用于调阈值）。

### 3.5 注入与缓存

| 内容 | 段 | 依据 |
|---|---|---|
| persona 四个必填槽 | 稳定前缀 | 只有改文档才变 |
| persona 卡 | 易变段 | 每轮可能不同 |
| memory 稳定事实 / 偏好 / 更正 | 稳定前缀 | 一天才变 |
| memory 经历 / 待办 | 易变段 | 随检索变化 |
| 时间 / 天气 / 生活状态 | 最后 | 永远最后 |

### 3.6 日记：三段式

| 层 | 内容 | 时机 |
|---|---|---|
| 存在 | 每天凌晨自己写、迷迷糊糊、写的是自己的一天、不主动给他看 | 常驻（能力槽） |
| 现状 | 写过几篇 + 最近三篇日期 + 最近一篇两三句摘要 | 每轮（易变段，一天变一次） |
| 正文 | 全文，>800 字截断 | 按需卡 `diary` |

关键句（务必保留）：

> 没带全文的时候别复述细节，说“想不起具体写了啥，要看吗”。

这句同时解决「否认写过」和「编造内容」两个坑。

## 4. 实施步骤

| 阶段 | 内容 | 工作量 | 回滚 |
|---|---|---|---|
| P0 | persona.md 槽位解析 + 长度校验 + 后台读写接口 | 0.5 天 | 删接口 |
| P1 | memory.md 结构改造（分区重排、出处字段、更正区） | 1 天 | 保留旧解析兼容 |
| P2 | 注入位置拆分（稳定/易变）+ 缓存隔离 | 0.5 天 | 开关切回单段 |
| P3 | 卡片触发改 embedding | 1 天 | 开关切回常驻 |
| P4 | 日记三段式（能力槽 + 现状注入 + diary 卡） | 0.5 天 | 关掉现状注入 |

依赖：P0 → P2 → P3；P1 与 P4 可并行。

## 5. 验收标准（可测）

1. `persona.md` 执行 `grep -E '深圳|杭州|小克|2026'` → **0 命中**
2. `memory.md` 执行 `grep -E '傲娇|嘴硬|雷区'` → **0 命中**
3. 发“你长什么样” → 日志含 `card=appearance score≥0.45`
4. 发“今天好累” → 日志 `cards=[]`
5. 发“你昨天日记写了啥” → 日志 `card=diary`，回复不提“用户/对话记录”
6. 改一行 persona → 下一轮生效，无需发版
7. 全量单测通过，路由快照同步

---

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 卡片触发不稳定（同义句漏） | 阈值可调 + 记录“最接近但未达标”的卡 |
| 记忆分区改造导致历史数据读不出 | P1 保留旧分区解析，双读一个月 |
| 人设失去系统微调能力（性格不再漂移） | 需要的话单独开`persona-drift`通道，不让提炼改人设 |
| 编辑表单与文件语法不一致 | 槽位解析器同时是校验器，后台保存时就报错 |

---

## 7. 明确不做

- 不做多套人设切换（先单份跑稳）
- 不把记忆拆成“短期/长期两库”（同一份文档 + 检索即可）
- 不做卡片的手动开关（触发由 embedding 决定，避免人肉维护）
- 不迁移历史数据（已清空，从白纸开始）
