## 1. 项目一句话

`ds-memory` 是一个部署在 Cloudflare Worker 上的私人长期记忆聊天系统：

```text
Worker + D1 + R2 + KV + Workers AI / DeepSeek
```

包含：

- 网页聊天（`public/index.html`）
- App（`ds-mobile`，Kotlin/Compose + Room）
- QQ/AstrBot 兼容端点（当前不作为主要使用端）
- 长期记忆、关系/情绪、主动消息、归档、摘要、影子引擎

## 5. 架构与数据流

### 写入

```text
App/Web 消息
→ Worker
→ D1 messages（原始对话）
→ R2 chat_logs/YYYY-MM-DD.log（每日归档）
→ 每日 04:00 提炼 memory.md / context
→ 周/月 rollup + summaries
→ memory_facts/events/chunks/entries/links
```

### 读取

```text
memory.md
→ extractPromptMemory（全量或 compact）
→ legacy memory_entries / next memory_chunks 召回
→ context-budget 分层预算
→ 角色 prompt
→ DeepSeek
```

### 关键存储

| 位置 | 用途 |
|---|---|
| R2 `memory.md` | 长期记忆事实源 |
| R2 `archive.md` | 历史档案（当前不是主路径） |
| R2 `chat_logs/YYYY-MM-DD.log` | 每日原始对话 |
| R2 `chat_logs/YYYY-MM.json` | 月度合并 |
| R2 `context/YYYY-MM-DD.json` | 当天上下文、天气、关系、提炼摘要 |
| D1 `messages` | 原始消息、幂等键、usage |
| D1 `memory_facts/events` | 结构化事实/事件 |
| D1 `memory_chunks/entries` | 召回索引 |
| D1 `memory_links` | 同实体/同事件关联 |
| D1 `memory_audit` | 轻量修改审计 |
| D1 `memory_rollups/summaries` | 周/月摘要 |
| D1 `cron_runs` | 归档任务幂等/状态 |

## 7. 当前已知问题

### 7.1 App 底部旧 pending

状态：

- 旧版本发送失败的 pending 仍可能存在；
- 新 App 已有“重试 / 删除”；
- 启动会做 `reconcilePending()`：
  - 服务端已有该 client_message_id → 自动删除；
  - 服务端没有 → 标记失败。

处理：

1. 重启 App；
2. 若仍显示失败，点“删除”；
3. 若想保留内容，点“重试”。

### 7.2 “顿了顿 / 顿了一下”偏多

已调整提示词，不禁止动作，只要求自然变化。

还需要观察：

```text
连续 20 条回复里出现次数
是否仍高频机械重复
```

### 7.3 DeepSeek 400 / 502

已确认根因是请求 JSON 中的落单代理字符：

```text
unexpected end of hex escape
```

已在 `requestDeepSeek()` 入口清理所有消息内容，并有紧凑重试。

需要：

- 用之前失败的同一条消息再试；
- 若仍失败，记录完整 error detail。

### 7.4 月度合并尚未真实验证

11/01 04:00 才会真实跑 `monthly_merge`。

已用单测覆盖跨天合法重复，但真实 R2 月文件回灌必须当天检查。

### 7.5 自动回归尚未每日执行

已有：

```text

```

但还没接每日 cron；当前 4 条样本，计划扩到 20 条。

### 7.6 记忆 UI 尚未做

来源追溯目前只有 admin API：

