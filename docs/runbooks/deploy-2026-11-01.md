### 身份是这次最大的行为风险

人设从「代码里写死 15 行」改成「只留骨架 + memory.md 的人物底色」。如果读不到 memory，她会变得很平。

排查顺序：

1. `/api/admin/readiness` → memory 字节数是不是 0
2. `/api/admin/memory/context-stats` → 分区在不在
3. 都正常但语气还是平 → 说明骨架太薄，把 `prompt.ts` 里兜底那句改成常态（一行代码）

## 4. 回滚

发布前记下的 version id，直接回退：

```powershell
npx wrangler rollback <version-id> -c wrangler.local.toml
```

**什么时候回滚**（任一命中就退，别现场调试）：

- `/health` 不通，或 5 分钟内恢复不了；
- 回复明显失忆、串台、编造事实；
- **她变得不像她**（不说"本小姐"、语气像客服、完全没有毒舌）；
- 归档链路报错且当天修不好；
- `recall-samples` 显示 `timedOutRate` 显著上升（>10%）。

回滚**不影响数据**：R2 的 memory.md、D1 的表都没被迁移，新版只是多读多写。
`chat_usage` 表留着无害（新代码不认它就只是张死表）。

## 5. 成本对照（发布后 3 天看）

部署前用 `/api/usage` 记的基线，和部署后 `/api/admin/cost` 对比：

| 指标 | 从哪看 | 预期 |
|---|---|---|
| 单条成本 | `cost.message` / `chat_usage.cost_rmb/calls` | 下降 |
| 缓存命中率 | `chat_usage.prompt_hit / (hit+miss)` | 0.6–0.85 |
| 7 天总费用 | `/api/usage` 的 `total_7d` | 比基线低 |

命中率长期低于 0.3 说明还有别的东西在打断前缀，按这个顺序查：

1. `historyNote` 或历史时间戳是否每轮重算；
2. `recalled`（相关往事）是不是被放进了稳定段；
3. `personaDrift` 是不是每轮变化（它现在在稳定段里）。
