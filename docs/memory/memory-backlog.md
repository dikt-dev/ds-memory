## M-01 分层上下文预算 + 注入清单

### 已完成（2026-10-28）

- `context-budget.ts`：core / recent / rollup / recall 分层装填；
- 固定记忆不裁剪；
- 超预算时先裁 recall，再裁 rollup，最后裁 recent；
- `openai.context` / `chat.context` trace 增加：
  - `budgetChars`
  - `budget`（各块 included/original/trimmed）
- 单测覆盖优先级和清单。

### 现状

已有基础限制：

```text
memory.md 全量上限 16KB
历史轮数 + 字符预算
context-packer 打包召回片段
```

缺少：

- 核心记忆 / 近期摘要 / 周月 rollup / 召回片段各自预算；
- 超预算时丢弃顺序；
- 每轮实际注入了哪些块、各多少字符。

### 方案

```text
固定记忆（称呼/底线/长期偏好）：约 2–3k 字符
近期摘要：约 2k
周/月 rollup：约 2k
召回片段：约 4k
总预算：约 10k 字符
```

每轮记录：

```text
memory.core_chars
memory.recent_chars
memory.rollup_chars
memory.recall_chars
memory.linked_items
memory.dropped_items
```

### 验收

- 总注入字符不超过预算；
- 固定记忆不被裁掉；
- 超预算时优先裁旧召回，不裁核心；
- trace 能还原本轮注入清单。

### 回滚

- 只改预算和 trace，不切记忆引擎；
- 关闭预算函数即恢复当前行为。

## M-02 自动回归集与每日离线评估

### 已完成（骨架）

- `scripts/memory-regression-cases.json`：固定样本；
- `scripts/memory-regression.mjs`：只读召回、校验 expect/forbid/linked 上限；
- `npm run memory:regression`；
- `GET /api/admin/memory/recall` 只读接口；
- 当前 4 条样本全部通过。

### 现状

已有回归方案：

```text
docs/plans/memory-regression-plan.md
```

但还没有固定样本和自动执行。

### 方案

1. 建立固定样本集：
   - 同事件：西湖/楼外楼；
   - 同实体：作息/上班/下班；
   - 无关：天气/快排/我回来了；
   - 冲突：旧作息 vs 新作息。
2. 每个样本人工标注“应该召回哪些记忆”。
3. 每日归档后跑一次离线评估：
   - 不写入用户记忆；
   - 输出命中率、噪声率、linked_items、注入字符；
   - 结果写入 `engine_metrics` 或单独表。
4. 设通过门槛后再考虑 `next`。

### 验收

- 样本集 ≥ 20 条；
- 每日自动跑；
- 连续 3 天指标稳定；
- 噪声率超阈值时有告警或记录。

### 回滚

- 评估只读，不影响线上；
- 可随时暂停 cron。

## M-03 跨日期近重复事实合并

### 现状

`canonicalizeFacts()` 已做：

- 同槽位去重；
- 新事实覆盖旧事实；
- 来源消息合并。

缺的是不同日期、不同槽位但语义相同的事实合并。

### 为什么不能直接做

错误合并会制造记忆冲突，例如：

```text
“我喜欢猫”
“我喜欢猫但不想养”
```

不能只靠 hash 或相似度直接覆盖。

### 方案

1. 先用 embedding 计算近重复候选；
2. 只对“同 section + 同 subject/predicate + 高相似度”生成候选；
3. 候选先进入待审队列，不直接删除；
4. 合并时保留来源消息 id 和两个版本的时间；
5. 冲突时保留新旧两条，标记 `valid_to`，不静默覆盖。

### 验收

- 近重复率下降；
- 不误合并“喜欢猫/不想养”这类反例；
- 合并后来源可追溯；
- 可回滚到合并前。

## M-06 静默结束后的主动消息暂停

### 现状

当前只做到：

```text
这一轮 AI 不回复
```

未做：

```text
静默结束 → 记录 closed_at
主动消息检查 closed_at → 暂停
用户再次发言 → 解除
```

### 风险

用户说“晚安，明天见”后，随机主动消息仍可能在夜里发出。

### 方案

- 静默结束时写 `conversation:closed_until`；
- 主动消息发送前检查；
- 用户新消息解除；
- 早晨/固定问候可配置是否豁免。

### 状态

用户要求先暂缓，等静默结束稳定后再做。

## M-09 遗忘机制

设计日期：2026-10-30。状态：设计已定，未实施。

### 结论

需要，但只做三种里的两种：**衰减、过期、合并**；**不做物理删除**。

差别不在技术，在产品：

| 做法 | 用户体感 |
|---|---|
| 删除条目 | 她真的忘了，追问也问不出来 → 像坏掉的硬盘 |
| 移出注入 / 降权 | 平时不提，追问还能想起来 → 像人 |

### 现状：已经在“忘”的部分

| 机制 | 位置 | 效果 |
|---|---|---|
| 日归档 → 月合并 → D1 清理 | cron | 原文离开热存储 |
| 分区预算降级 | `demoteSectionEntries` | 超预算时最旧条目移出提示词（文件仍在） |
| 召回粗衰减 | `memory-index.ts:800` | >60 天 ×0.5，>90 天 ×0.25 |
| 召回上限 | top-8 | 没被召回 = 不进上下文（软遗忘） |
| 覆盖式更新 | `OVERWRITE_HEADERS` | 「偏好与习惯」「关于用户」按 key 原地覆盖 |
| 情绪衰减 | `emotion-vector.ts` | 8 维独立半衰期；**委屈不衰减**，要人哄才消 |

> 情绪那套是现成的正确范式：不同维度不同速度，且有故意不忘的一维。记忆也该这样。

### 缺口

| # | 缺口 | 证据 |
|---|---|---|
| 1 | 状态类记忆没有期限 | 「进行中的事项」一直堆，三个月前的“正在重构”还挂着 |
| 2 | “提到过”与“重要”同权 | 打分无访问频次、无最近提及加权 |
| 3 | chunks 只增不减 | 87 条已 503ms；+10/天 → 一个月 400+ 条，每次读 600KB |
| 4 | 重复事实 | 同一件事在「共同经历」里可能 2–3 条（M-03） |

### L1 衰减（最便宜，先做）

现状只有 60/90 天两档，补一档并加“最近提及”维度：

```text
>30 天 ×0.75      （新增；配合现有 >60 ×0.5、>90 ×0.25）
最近 7 天被提及过 ×1.2   （用「上次提及时间」加权，不新增存储）
```

#### 红线：被追问时不做衰减

Query 命中「第一次 / 去年 / 最早 / 那时候 / 还记得」这类明确指向时，**跳过全部时间衰减**。

不做这条的后果：三个月后用户问“你还记得我们第一次聊什么吗”，回答“没印象”。
**这一条的伤害远大于遗忘带来的任何性能收益**，属于设计硬约束。

### L2 过期（只对状态分区）

| 分区 | 期限 | 过期后 |
|---|---|---|
| 近期动态 | 7 天 | 移出提示词注入 |
| 进行中的事项 | 14 天 | 移出注入，召回权重 ×0.3 |
| 关于用户 / 偏好与习惯 / 雷区 / 共同经历 | 永久 | 不变 |

过期 = 不再每轮注入；文件里那行还在，检索仍可召回。

### L3 合并（= M-03，最有价值也最贵）

同一件事的多个碎片合成一条，例如：

```text
现在: - 他说想换工作
      - 他在看杭州的岗位
      - 他投了一家做后端的公司
合并: - 想换工作，在看杭州后端岗，已投一家（26-10 更新）
```

需要样本积累，等 11-07 之后做。

### 优先级：索引 > 合并 > 衰减 > 过期

**遗忘机制解决不了 O(N)。**

```text
87 条 chunks  → 503ms（已测）
+10 条/天     → 一个月 400+ 条 → 约 2s
删掉一半      → 延迟只降一半，三个月后照样涨回来
```

真正到期必须换的是倒排索引（token → chunk id 常驻 KV，按 id 取正文），把 O(全部) 变成 O(命中)。那是 Phase 6 的事。

所以顺序：

| 顺序 | 事项 | 何时 |
|---|---|---|
| 1 | 倒排索引 | Phase 6（不做会变事故） |
| 2 | M-03 近重复合并 | 11-07 后，有样本 |
| 3 | L1 衰减（含红线） | 随时，约 2 小时 |
| 4 | L2 状态过期 | 随手，约半天 |

### 验收

| 项 | 标准 |
|---|---|
| 衰减不影响追问 | 问“第一次提到 X 是什么时候”，能答出且带日期 |
| 状态过期生效 | 15 天前的「进行中的事项」不再出现在提示词里 |
| 召回质量不降 | 回归集（M-02）的命中率不低于改动前 |
| 延迟不升 | `recall-samples` 的 p50 不高于改动前 10% |

### 回滚

两者都是纯读侧逻辑（打分系数、注入过滤），改一个常量即可回退，不涉及数据迁移。

### 明确不做

- 不物理删除用户说过的话；
- 不用遗忘机制替代索引优化；
- 不给「雷区与禁忌」设过期（踩过的坑必须永久生效）。
